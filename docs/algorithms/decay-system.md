# 衰减系统（记忆曲线）

衰减系统根据页面的重要性、创建时间、使用次数和固定状态计算一个分数。维护命令可以据此将低分页面标记为 `dropped`，使其退出普通召回，同时保留原文件供检查和恢复。

这个分数用于管理知识页，不表示内容正确的概率。旧知识可能仍然正确，新知识也可能有误；是否可信仍需查看来源、适用条件和审核记录。

## 分数如何计算

`store.py` 中的 `compute_score()` 使用以下公式：

```text
基础分 = importance × exp(-λ × days_old)
使用加分 = 0.5 × ln(1 + access_count)
固定加分 = 页面被固定时取 pin_bonus，否则为 0
score = 基础分 + 使用加分 + 固定加分
```

计算后，`status: active` 的页面再乘 1.2。已归档或 `status: dropped` 的页面直接返回 0。

| 参数 | 含义 |
| --- | --- |
| `importance` | 页面的重要性；缺失时按 0.5 计算 |
| `λ` | 时间衰减速度；数值越大，基础分下降越快 |
| `days_old` | 从页面 `created` 时间算起的天数；时间缺失或无法解析时按当前时间处理 |
| `access_count` | 显式记录的使用次数，不是搜索命中次数 |
| `pin_bonus` | 固定页面的加分，默认 0.5 |

`exp` 表示指数函数，`ln` 表示自然对数。对数项让后续每增加一次使用带来的加分逐渐变小，但总分仍可能超过 1，因此不能把 `score: 0.8` 解读成“80% 可信”。`confidence` 不参与这个公式。

## 不同类型的时间衰减

当前默认值如下：

| 类型 | `λ` | 计算行为 |
| --- | ---: | --- |
| `concept`，概念 | 0.000 | 基础分不随时间降低 |
| `strategy`，方法 | 0.014 | 基础分随时间降低 |
| `anti-pattern`，应避免的做法 | 0.010 | 基础分降低速度慢于 `strategy` |
| 未识别的类型 | 0.030 | 使用备用值，基础分降低更快 |

这些是经验参数，尚无长期量化评测证明它们适用于所有知识库。`concept` 的系数为 0，只表示当前公式不给概念页施加时间衰减，不代表概念永远正确或不需要修订。

例如，一个未固定、从未记录使用、`importance: 0.5` 且为 `active` 的 `strategy` 页面，创建当天的分数为 `0.5 × 1.2 = 0.6`。约 50 天后，分数为 `0.5 × exp(-0.014 × 50) × 1.2 ≈ 0.298`。如果期间没有其他变化，再运行衰减命令时，它会低于默认阈值 0.3。

## 分级和退出阈值是两回事

系统会按分数给页面分级，便于查看知识库状态：

| 分级 | 分数范围 |
| --- | --- |
| `hot` | 大于或等于 0.7 |
| `warm` | 大于或等于 0.4，小于 0.7 |
| `cold` | 大于或等于 0.15，小于 0.4 |
| `evictable` | 小于 0.15 |

这些标签本身不会删除文件，也不直接决定 FTS5 的排序。native 检索会将记忆分作为相关性的一项，FTS5 则使用自己的文字匹配分数，区别见[召回引擎](recall-engine.html)。

维护时采用的是另一个参数 `archive_threshold`，默认值为 **0.3**。它与 `evictable` 的边界 0.15 不相同。例如，分数为 0.2 的页面属于 `cold`，运行衰减时仍会低于退出阈值。

## 何时修改页面状态

衰减不是自动运行的后台定时任务。相关维护命令的行为如下：

| 命令 | 行为 |
| --- | --- |
| `oks decay` | 检查页面分数，将低于阈值的页面标记为 `dropped` |
| `oks distill` | 执行衰减，并根据共享标签的知识页生成待审核提议 |
| `oks distill --dry-run` | 只报告将检查的 Wiki 页面数量，不修改页面，也不预测每页是否会退出召回 |

`apply_decay()` 跳过已归档、已固定和已经 `dropped` 的页面。其余页面若分数低于阈值，会在**这一次命令运行中**写入 `status: dropped`，不会先等待下一轮。Markdown 文件仍保留在原处。

固定页面有两种作用：评分时得到 `pin_bonus`，维护时直接跳过自动退出处理。固定并不意味着公式中的时间项停止衰减，也不表示内容已经过人工核验。

`oks distill` 的提议来自已有知识页的规则分组。它不会调用模型读取原始材料并提炼内容，也不会批准生成的提议。

`archive_threshold` 和 `pin_bonus` 目前是 `store.py` 的代码默认值。内部函数可以接收传入的配置，但普通 CLI 调用不会从 `settings/recall.yaml` 覆盖这两个参数。Studio 中的曲线预览也不等于已经修改了实际维护规则。

## 归档与恢复

自动衰减和显式归档保留文件，但写入的字段不同：

| 操作 | 写入的状态 |
| --- | --- |
| 自动衰减 | `status: dropped` |
| 显式归档 `archive` | `status: dropped`，同时设置 `archived: true` |
| 恢复 `unarchive` | `status: provisional`，同时设置 `archived: false` |

恢复操作不会补写一次人工审核，也不会直接设置成 `active`。恢复后页面是否出现在某次查询中，还取决于查询范围、匹配内容和其他筛选规则；不能把 `provisional` 一概理解为永不参与召回。

可恢复意味着误退出的页面仍有办法找回，并不意味着退出没有影响。在恢复之前，查询可能缺少原本有用的内容。

## 使用次数与置信度分别记录什么

搜索和阅读不会增加使用次数。只有显式执行 `oks use` 或 `oks wiki use` 记录采用情况，才会增加 `access_count`。这一操作不修改 `confidence` 或 `status`。因此，页面经常被采用可以提高记忆分，却不能代替内容审核。

`confidence` 是单独保存的元数据。当前实现会在以下情况下更新它：

| 情况 | 更新规则 |
| --- | --- |
| 内容指纹匹配已有页面，且调用方没有传入置信度 | `min(1, current + 0.1 × (1 - current))` |
| 调用方显式传入置信度 | 使用传入的值 |
| 对已有页面建立 `confirms` 关系 | 原值加 0.1，最大为 1 |

内容指纹用于判断文本内容是否相同。它不能证明两份内容来自独立来源，也不能证明有人独立验证了结论。上述更新只是程序对元数据的处理规则，不能据此断言内容获得了新的可靠证据。

维护者排查知识质量时，应分别查看：内容从哪里来、是否有审核记录、什么情况下被使用，以及当前为什么参与或退出召回。不要用单一分数代替这些判断。

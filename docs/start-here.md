# 开始使用

OKS 的核心使用条件只有两个：本机可以运行 `oks` CLI，并且已经选择或创建一个知识库。使用 Agent 操作时，建议再为当前宿主安装 OKS Skill，让 Agent 知道各类内容应该怎样保存和审核。

Agent 是当前执行任务并调用 OKS 的主体。CLI 负责创建目录、保存记录和查询，知识库负责长期保存文件，Skill 为 Agent 提供操作规则。它们不是同一个东西。

## 先确认你现在处在哪一步

| 当前情况 | 从哪里继续 |
|---|---|
| 从未安装或不确定是否安装 | 从[安装与创建知识库](installation.html)开始 |
| 已安装 CLI，但没有知识库 | 创建一个个人知识库，再运行 `oks status` 确认位置 |
| 已有知识库，希望让当前 Agent 使用 | 检查 OKS Skill，并确认 Agent 连接的是正确知识库 |
| CLI、Skill 和知识库都可用 | 直接完成[第一次实践](first-knowledge-loop.html) |
| 已经熟悉基本流程 | 按需要进入[日常任务](usage/) |

如果机器上已经有知识库，先沿用它，不要为了重新学习再创建一份。个人知识库与 OKS 源码仓库是不同目录；知识应保存在知识库实例中。

## 哪些是必要的

| 组成 | 是否必需 | 用途 |
|---|---|---|
| `oks` CLI | 必需 | 创建、检查和操作知识库 |
| 个人知识库 | 必需 | 保存个人的 Raw、Candidate、Wiki 和其他记录 |
| OKS Skill | 使用 Agent 时建议安装 | 告诉 Agent 如何调用 CLI、保留证据和等待人工审核 |
| 团队知识库 | 可选 | 读取和贡献团队维护的知识 |
| Hook | 可选 | 在宿主支持时自动执行 Recall 或冲突检查 |
| Studio | 可选 | 在本地网页中浏览讨论、目标、知识关系和评测记录 |

首次实践不依赖团队库、Hook 或 Studio。你可以在对话中明确要求 Agent 查询知识，先确认核心流程可用，再决定是否启用其他功能。

## 推荐的首次路径

1. 安装 CLI，选择已有知识库或创建新的个人知识库。
2. 安装 OKS Skill，让 Agent 读取当前知识库并报告实际路径。
3. 用一份短材料完成 `Source → Raw → Candidate → 人工审核 → Wiki → Recall`。
4. 在新会话中确认 Agent 仍使用同一个知识库，并能展示 Recall 命中和来源。

安装与连接的具体检查见[安装与创建知识库](installation.html)。首次实践会逐步说明每一步的输入、产物和验收方法。

Studio 的“讨论”“目标”“学习”页面可以帮助组织问题、目标和学习过程，但不是所有 OKS 操作都必须经过的固定流程。它们也不等同于 Raw、Candidate 和 Wiki 的内容状态。

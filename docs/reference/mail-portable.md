# Mail 接入

让你正在使用的 Agent 连接知识库并打开面板：

```text
帮我打开这个知识库的 OKS Mail 面板。
先检查已有服务，能复用就直接打开；没有再启动本地服务。
确认连接的是哪个知识库，并告诉我浏览器地址。
```

## 让另一个 Agent 接着做

在负责交接的 Agent 中说：

```text
为这项工作准备一份交接，写清目标、已完成的事、产物位置、
当前阻塞和建议的下一步。先展示交接内容并确认实际接收人，
得到我的发送指令后再发送，不要把已发送写成已执行。
```

接收方需要在自己的会话中读取同一知识库的 Mail，再按约定继续或回复。没有接收人或可用的宿主接入时，应说明缺口；Mail 本身不会唤醒 Agent。

## 看什么结果

面板展示通信记录、消息详情及可观察的读取或回复状态。它们分别说明发生了什么，不能合并成“工作已完成”。知识和候选通过引用关联，新的知识仍需人审。

如果 Agent 运行在知识库目录之外，让它检查自己的 Skill 发现位置和知识库绑定。先展示拟连接的实例与身份，不覆盖已有绑定；本机绑定不应放进团队仓库。

## 下一句可以这样说

```text
读取与这项工作有关的交接，先确认现状和待办，再告诉我你准备从哪里继续。
```

典型场景见 [oh-my-handoff](../oh-my/handoff.html)。Agent 或开发者需要手工接入时，查看 [CLI 接入细节](cli.html#mail-接入)与 [Mail 协议](mail-protocol.html)。

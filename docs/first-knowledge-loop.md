# 第一次知识循环

本教程用一份小材料走完：**保存来源 → 提出候选 → 你来审核 → 新任务引用**。完成后，你能找到知识的来源、审核决定和后续使用结果。

开始前，先[安装并创建知识库](installation.html)，让 Agent 确认当前实例的位置。下面是教程样例，仅适用于“示例项目”，不代表你的真实项目约定。

## 1. 保存这份材料

把这段话连同样例一起交给 Agent：

```text
请将下面这份教程样例收录到 OKS，保留原文与来源，
提出一条只适用于“示例项目”的待审核知识。
先打开来源与候选让我看，不要直接保存为长期知识。

标题：示例项目的问题说明约定
性质：教程样例，仅用于示例项目。
提交问题说明时，应包含复现步骤、预期结果和实际结果。
本材料未规定问题优先级、负责人或修复时限。
```

**查看结果：** 让 Agent 打开保存的来源和候选正文。来源应保留原文；候选应表达“三项问题说明内容”，不能补出修复时限。此时它仍是待审核候选（Candidate），不是已确认知识（Wiki）。

## 2. 做出审核决定

先让 Agent 展示提议与来源：

```text
把这条待审核提议和对应来源一起展示给我，说明适用范围和没有证据的部分。
```

核对候选与来源一致、适用范围仍是“示例项目”。预期内容类似：

> 教程样例：示例项目的问题说明应包含复现步骤、预期结果和实际结果。

如果你认可将这条样例保存到当前知识库，就明确告诉 Agent 接受这条候选；需要修改、拒绝或暂不决定，也直接说明。

**查看结果：** 接受后，让 Agent 展示长期知识及对应审核记录。拒绝或暂不决定时，它不能进入 Wiki；本次流程可以停在这里，无需为了完成教程而接受。

## 3. 在新任务中引用

接受候选后，开启新会话，连接同一个知识库，交给 Agent 一个新问题：

```text
请先查询 OKS 中“示例项目”的已审核知识。
现在有人只报告“导出失败”，提交问题前还应补充什么？
请说明用了哪条知识，以及它的来源。
```

**查看结果：** Agent 应找到并引用刚才审核的知识，要求补充复现步骤、预期结果和实际结果。让它展示知识条目与来源；仅凭回答碰巧列出这三项，不能证明发生了召回。

再问“示例项目承诺多久修好？”材料没有这一约定，Agent 应说明信息不足。

## 确认完成

当来源能打开、候选经过你的明确决定、新会话实际引用了已审核知识时，这次循环才完成。若只保存了来源或候选，就保持当前状态，继续处理缺失步骤。

## 遇到问题

| 现象 | 让 Agent 先检查 |
|---|---|
| 找不到实例或新会话查不到知识 | 两次会话是否连接同一个知识库 |
| 来源或候选没有保存 | 收录结果、缺失能力与原始错误 |
| 接受后没有长期知识 | 是否记录了审核决定，保存目标是否正确 |
| 回答没有引用这条知识 | 是否真正执行了查询，命中的条目是否相关 |

Agent 主动查询可用而自动引用失败时，再让它检查宿主的自动召回是否启用。未完成的步骤保留原状态；详细排查见[故障排除](reference/troubleshooting.html)。

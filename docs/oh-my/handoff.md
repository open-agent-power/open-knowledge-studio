# oh-my-handoff · 工作交接

示例场景：长任务需要暂停、换会话或交给另一个 Agent。本页提供交接提示，不包含已发送的消息或已完成的接手记录。

## 遇到什么事

产物已经生成了一部分，还有未解决的阻塞。下一次会话需要知道从哪里继续，避免重做已完成的工作或误把未验证结果当作完成。

## 交给 Agent

```text
帮我为这项工作准备交接，保存目标、已完成事项、产物、
实际验证结果、阻塞和下一步，告诉我记录在哪里。
如需通过 Mail 发给另一位 Agent，先确认接收人并让我看交接内容。
```

记录中保留 `partial`、`failed` 和 `skipped` 等实际状态。接收人尚未确认时，不把发送写成已完成。

## 在哪里看结果

- 交接内容能找到当前产物和验证证据，并明确下一步。
- 通过 Mail 交接时，在同一 Thread 中查看消息、后续回复和读取回执。
- 下一次 Session 读取记录后，再核对工作现场与尚未完成的事项。

Mail 保存交接事实，不会自动启动或唤醒对方 Agent。已保存、已读取和已执行是不同状态。

## 下一句怎么说

```text
读取这项工作的交接，核对当前产物和阻塞。
先告诉我哪些已完成、哪些还缺证据，再从下一步继续，并引用交接记录。
```

跨机器交接前，需要按团队流程交换知识库文件。Agent 的回复和执行结果继续回到原 Thread，形成可追溯的后续记录。

接入步骤见 [Mail 接入](../reference/mail-portable.html)，职责说明见[协作边界](../concepts/product-boundary.html)。

# oh-my-project · 项目经验

示例场景：一次缺陷修复结束后，把复现方法、修复原因和验证结果整理成后续任务可用的经验。本页提供工作提示，不包含已执行的修复记录。

## 遇到什么事

同类问题反复出现，每次换会话都要重新解释。代码补丁还在，但“为什么这样修”和“怎样确认修好”没有留在一起。

## 交给 Agent

```text
把这次修复整理成以后能复用的项目经验。
先查已有约定，再根据复现步骤、改动和测试结果提出候选，
附上来源与适用范围，等我审核后再保存。
```

可以把具体问题、相关文件或已有修复记录一起交给 Agent。缺少复现或测试结果时，先补证据。

## 在哪里看结果

- 来源记录：这次问题怎样复现，改了什么，哪些检查实际运行过。
- 待审核提议：经验、适用范围，以及对应的来源位置。
- 审核后的知识：只包含你明确接受的内容，保留这次决定。

确认内容时可以说：“保留这条经验，但把适用范围限定为当前项目；没有运行过的检查继续标为未验证。”

## 下一句怎么说

```text
现在处理这个相似问题。先查已审核的项目经验，
说明哪一条适用、哪里需要重新验证，再提出做法并附上引用。
```

如果没有相关知识，Agent 应说明缺口。新的修复结果仍先整理为候选，由你决定是否补充或修订旧知识。

审核操作见[审核知识](../usage/review.html)，后续使用见[召回知识](../usage/recall.html)。

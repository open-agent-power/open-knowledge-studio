# 审核 Candidate

审核是对 Candidate 的具体版本作出决定。文件名相同但正文已经修改，就应重新阅读；旧决定不能自动覆盖新版本。

```text
请展示待审核知识及其来源、与已有知识的关系和未核验内容；
等我决定后再保存审核结果。
```

## 先检查五件事

1. **证据**：重要主张能否在 Raw 或其他明确来源中找到支持。
2. **表述**：来源事实、来源作者观点和 Agent 推断是否分开。
3. **范围**：项目、版本、日期、用户或前置条件是否保留。
4. **复用价值**：内容是否比原始材料更容易在后续任务中直接使用。
5. **与旧知识的关系**：是新增、补充、印证、质疑，还是取代现有页面。

例如，来源只说明“项目甲的问题报告应包含复现步骤、预期结果和实际结果”，Candidate 就不应增加“必须在一天内修复”，也不应把这条规则扩展到所有项目。

## 可以作出哪些决定

| 决定 | 适合的情况 | 结果 |
|---|---|---|
| 接受当前版本 | 内容、证据和范围都合适 | Promote 为 `active` Wiki，并写入审核记录 |
| 修改后再审 | 需要改正文、范围、分类或关系 | 先修改 Candidate，再展示新版本，不沿用旧决定 |
| 拒绝当前版本 | 缺少依据、错误、重复且无补充价值 | 保留拒绝记录，不写入 Wiki |
| 暂不决定 | 还需补来源或请其他人确认 | Candidate 继续待审核 |

“修改后接受”应拆成两个动作：先修改并重新展示，再明确接受看到的版本。这样审核决定才能对应确定内容。

## Promote 后发生什么

执行 `oks drafts promote` 时，CLI 在审核锁内读取 Candidate 当前版本。成功后：

- Wiki 页面写入 `status: active`；
- 写入 `human_reviewed_at`；
- 保存来源 Candidate 和审核证据；
- 如果声明了 `supersedes`、`enriches`、`confirms` 或 `challenges`，同步更新旧页的关系或状态；
- 普通 Candidate 的决定记录会保留，后续可核对当时接受的内容。

执行 `oks drafts reject` 会保存拒绝决定，不生成 Wiki。审核记录说明当前版本被接受或拒绝，不表示内容已经由独立来源证实，也不保证以后仍适用。

## 不要混淆直接创建 Wiki

`oks wiki create` 可以直接写入 `wiki/`，但默认创建的是 `status: provisional` 页面，不带 `human_reviewed_at`。它不等同于 Candidate Promote，也不能用来声称某条内容经过了人工审核。

对于从材料提炼出的新结论，优先走 Raw → Candidate → 审核 → Wiki，以便保留证据和具体版本的决定。

## 完成后检查

- 实际处理的是你刚刚看过的 Candidate 版本。
- 接受后的 Wiki 正文、范围和关系与你的决定一致。
- 页面状态和 `human_reviewed_at` 符合预期。
- 拒绝有记录，暂缓项仍在待审核队列。
- 旧页被替代或质疑时，状态和反向关系已经更新。

接着在一个新问题中运行 Recall，检查页面是否能被找到，并阅读[查询与引用](recall.html)。知识变化后的处理见[修订、替代与归档](maintain.html)。

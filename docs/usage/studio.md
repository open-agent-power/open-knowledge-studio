# 本地 Studio

Studio 是 OKS 随本地服务提供的网页界面。它直接读取所选知识库中的文件，用来查看讨论和目标、浏览知识关系、审核 Candidate、检查查询过程，以及运行检索评测。

Studio 不是另一套知识库。页面关闭后，知识仍保存在实例目录中；允许编辑时，保存操作也会写回这些文件。浏览器里的筛选条件、展开状态和临时输入不是知识记录。

## 启动 Studio

在知识库所在电脑上运行下列命令之一：

```bash
# 只读查看
oks mail serve --path <知识库路径>

# 查看并审核 Candidate
oks mail serve --path <知识库路径> --local-review

# 审核并编辑讨论、目标、参数和知识库配置
oks mail serve --path <知识库路径> --local-edit
```

命令会打印类似 `http://127.0.0.1:3182/` 的地址。服务只绑定本机回环地址，其他电脑不能直接通过局域网访问。可以用 `--port` 更换端口。

三种启动方式的权限不同：

| 启动方式 | 可以做什么 |
| --- | --- |
| 默认 | 浏览讨论、目标、知识图谱和文件；查询知识；查看已有历史与评测结果 |
| `--local-review` | 包含只读能力，并可审核 Candidate 和反馈记录 |
| `--local-edit` | 包含审核能力，并可编辑讨论与目标、保存可调参数、配置个人库和团队库、导入和运行评测 |

`--local-review` 和 `--local-edit` 只能用于前台服务，不能与 `--background`、`--status` 或 `--stop` 组合。旧参数 `--mode collaboration` 控制的是 Mail 的兼容写入接口，不会开启 Studio 编辑权限。

打开页面后，先看右上角显示的知识库。路径不对时不要继续编辑或审核。

## Studio 怎样读写数据

Studio 通过本地 HTTP 接口读取知识库文件和 OKS 记录。允许写入时，页面会连同读取时的文件版本一起提交保存请求。如果文件已经被其他窗口或工具修改，服务会拒绝覆盖，要求重新读取后再处理。

讨论和目标通常按日期保存：

```text
profiles/discuss/YYYY/MM/DD/<标题>.md
profiles/goals/YYYY/MM/DD/<标题>.md
```

旧的 `discuss/` 和 `goal/` 路径仍可读取。日期来自目录结构，不根据文件修改时间推断。把文件放进某一天的目录，只表示归档位置，不表示目标已经完成。

Studio 根据文件中明确写出的引用、元数据和执行记录建立页面关系。两个文件内容相似，不会因此自动建立引用；文档写了步骤或引用了 Skill，也不代表 Agent 已经执行。

## 讨论

“讨论”默认显示所选日期的讨论历史。它适合记录问题、人的判断、Agent 的理解、相关目标和引用材料。页面中的连线来自文档里明确写下的关系，用来帮助回查上下文。

启用 `--local-edit` 后，可以新增或修改讨论。保存只更新讨论文件，不会自动启动 Agent，也不会把讨论内容转成 Candidate 或 Wiki。需要 Agent 继续处理时，应在宿主会话中明确交代任务，并在完成后检查实际产物和记录。

## 目标

“目标”按日期读取目标文件。思维图适合查看层级和完成状态，“原文”用于阅读或编辑完整 Markdown。启用 `--local-edit` 后，可以新增目标和子项、修改标题、勾选完成状态，或直接编辑原文。

页面上的完成勾选是文件内容的一部分。它不验证任务是否真的完成，也不会替代测试、验收记录或执行结果。目标详情中的“流程与执行”会分别展示文档结构和匹配到的运行记录，两者应分开判断。

## 学习

“学习”面向整个知识库，不随日期切换，包含四个子页。

### 图谱

图谱可以浏览 Wiki、Candidate、Raw、Profile、项目、目标、讨论，以及知识库管理的 Skill。颜色、深浅、节点大小和虚线分别表示页面中给出的类型、显式使用次数、分支规模和待审核状态。

筛选、圈选、展开和折叠只改变当前视图，不修改文件。图谱关系来自文件中的显式引用和元数据，不表示内容正确，也不表示相关工作已经执行。

在搜索框输入文字只会筛选当前图谱。点击查询或按回车后，Studio 才会调用 Recall，并显示实际返回结果、后端和诊断信息。页面显示的耗时包含本地 HTTP 往返和页面处理，不能直接当作检索算法本身的耗时。

### 文件

文件页通过 OKS 的只读 VFS 浏览当前实例。它可以列目录、打开文件、分段读取正文，并展示本次 VFS 调用和近期调用记录。

这个页面不是文件编辑器。它不会写入、移动或删除文件，也不能绕过 Candidate 审核和 Wiki 状态检查。可访问范围由 VFS 的 scope（访问范围）决定，关联团队库后可能出现只读的 `team` scope。

### 参数

参数页展示检索、正文注入预算、记忆曲线（Memory Curve）和运行配置。部分参数可在 `--local-edit` 模式下保存，固定算法常量只读。

公式和曲线是计算预览。修改参数后看到分数或曲线变化，不能证明 Recall 变好，更不能证明 Agent 的回答正确。需要比较效果时，应使用同一份评测数据和可比较的知识库快照。

### 评测

评测页用于检查一组查询能否找到预期知识。只读模式可以查看已有数据集、运行记录和结果；导入数据、启动评测和保存评测审核需要 `--local-edit`。

评测结果衡量的是检索行为，例如预期条目是否出现、排在什么位置、请求用了多长时间。它不检查 Agent 是否正确理解条目，也不证明任务已经完成。两次运行只有在数据、语料和必要配置可比较时，分数差异才有明确含义。数据格式、指标和比较限制见[召回评估](../algorithms/recall-evaluation.html)。

## 审核 Candidate

Candidate 是 Agent 根据来源材料整理出的待审核版本。Candidate 不是 Wiki，也还没有审核决定。查看 Candidate、搜索命中或在图谱中打开它，都不会产生审核决定。

使用 `--local-review` 或 `--local-edit` 启动后，可以打开 Candidate 的正文、来源和当前版本，再决定通过或拒绝。审核针对眼前这个具体版本；正文发生变化后，应重新阅读，不能沿用旧结论。

通过审核会生成带审核记录的 `active` Wiki。拒绝会保留拒绝记录和原 Candidate，供以后查明当时为什么没有入库。审核前应核对知识库路径、Candidate 路径、正文和来源。完整步骤见[审核 Candidate](review.html)。

## 切换个人库和配置团队库

右上角的知识库入口显示当前个人库和已配置的团队库。修改配置需要 `--local-edit`。

选择文件夹只会把路径填入表单。个人库要执行“切换”后才会应用，团队库要执行“保存”后才会写入配置。取消选择不会改变现有设置。系统没有可用的桌面文件夹选择器时，可以手工输入路径。

切换个人库后，应重新确认页面标题和路径，再继续编辑或审核。团队库仍按只读 Git 关联规则工作，Studio 不会自动拉取仓库、切换分支或执行其中的代码。具体规则见[个人库、团队库与工具仓库](../knowledge-repositories.html)。

## 历史记录能说明什么

讨论和目标页面的时间线读取 Studio 已保存的版本记录。选择较早的节点时，页面展示历史快照并进入只读状态；回到当前版本后才能继续编辑。

在 Studio 中保存时，记录包含提交时的前后内容。只有 `--local-edit` 会启动外部文件观察器，用来发现编辑器或其他 Agent 对讨论、目标和 Candidate 文件的修改。观察器第一次看到文件时只建立 `baseline`（比较基准），不把已有内容记作一次修改；后续记录中的 `observed-at` 是观察器发现变化的时间，不一定是文件实际修改时间。

时间线不是 Git 的完整历史。服务没有运行时发生的多次修改，可能只留下最终结果；开始观察以前的版本也不会自动补齐。时间线和图谱都不记录 Agent 的内部推理。

## 使用边界

- Studio 展示文件和记录，不会仅凭页面关系判断内容正确。
- 文件页只读，编辑应使用对应的 Studio 功能、CLI 或宿主工具。
- Recall 命中、Hook 注入、Agent 采用、`oks wiki use` 和人工审核是不同事件。
- 参数预览和评测分数只说明各自测量到的结果，不能替代任务验收。
- Studio 不会自动同步团队 Git 仓库，也不会因为打开页面而启动 Agent。

命令参数见 [CLI 参考](../reference/cli.html)。查询与使用记录的区别见[查询、使用与评测记录](../linked-knowledge-observability.html)。

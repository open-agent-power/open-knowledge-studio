# 召回知识

```text
请先查找当前任务相关的已审核知识，打开相关原文，再回答我的问题；说明用了哪些条目、哪些内容可能过时，证据不足就指出缺口。
```

一并说明具体问题与项目范围。Agent 查询后，应读取相关条目，再把适用的知识用于回答。

## 看什么结果

- 回答引用了具体知识条目，并能打开来源。
- 已审核知识、待确认推断、可能过时的内容分别说明。
- 没有把原始材料当作已确认判断，也没有用相似内容补出来源不支持的结论。

相关性只影响排序，不能证明内容正确。没有命中时，先确认当前知识库是否存在相关知识，再补充问题背景；知识过时或冲突时，补充来源并重新审核。

## 希望自动查询时

可以继续说：“请检查当前 Agent 是否支持自动召回，说明启用方式和限制，先不要改配置。”

自动召回依赖宿主支持与相应设置；没有启用时，仍可直接要求 Agent 查询。技术细节见[CLI 参考](../reference/cli.html)，排序原理见[召回引擎](../algorithms/recall-engine.html)。

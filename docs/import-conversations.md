# 导入对话

可以把已有的项目讨论或问题处理记录作为 Raw 保存，再从中整理 Candidate。对话里说过什么、用户明确作过什么决定、Agent 后来作了什么推断，需要分别标明。

```text
请用 OKS 把这段对话保存为 Raw，保留原文位置、时间和缺失范围。
区分我明确作出的决定与 Agent 的推断；把值得以后使用的内容整理为 Candidate，
写清证据和适用范围。等我审核后再 Promote，不要直接称为已审核知识。
```

优先选一段有明确结果的项目讨论、排障或复盘。已经过时、缺少上下文的片段，可以先不导入。

## 提供什么材料

- **当前 Session**：让 Agent 检查 Host 是否能提供完整记录；不能取得时，由你提供文本或导出文件。
- **其他平台的对话**：提供导出的 Markdown、纯文本或受支持的结构化文件。需要登录的分享链接通常不足以取得可复核的完整内容。

导入前排除密钥、Cookie 和不适合保存的私人信息。脱敏后保留必要的来源位置，不保留秘密本身。

## 看什么结果

- 保存的对话能回到原文；不完整的记录标明缺失范围。
- Candidate 区分“你明确确认过的决定”和“Agent 的推断”，可能随时间变化的内容注明日期与复核要求。
- 同主题内容优先说明与已有 Wiki 的关系；新 Candidate 仍待你审核，不会自动带上审核记录。

下一句可以说：“请展示这次对话形成的 Candidate，逐条附上原文。”接着[审核 Candidate](usage/review.html)。

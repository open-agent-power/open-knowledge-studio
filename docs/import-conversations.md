# 导入对话

不要把全部聊天记录一次性转成长期知识。先保存原文，再让 AI 提出 Candidate，最后由人决定哪些内容值得复用。

## 保存当前会话

在支持 Skill 的 Agent 中使用：

```text
/archive
```

`/archive` 将对话原文保存到 `raw/conversations/`，并把可复用的 Q&A 提议写入 `drafts/`。它不会直接写 Wiki。

## 导入外部对话

先从对应平台导出 `.md`、`.txt` 或受支持的结构化文件，再对 Agent 说：

```text
请使用 /ingest 收录这份对话导出。保留完整来源，
只把可独立复用的判断写成 Candidate，不要自动晋升。
```

若平台无法导出，需要你提供对话文本或本地文件。仅提供一个需要登录的链接通常不足以形成可复核 Evidence。

## 选择导入范围

优先处理：

- 仍在使用的项目决策；
- 有明确结果的排障和复盘；
- 反复需要解释的背景；
- 能够回到来源的个人判断。

暂缓处理：

- 大量闲聊或临时问答；
- 已过时且无法核验的结论；
- 缺少必要上下文的片段；
- 包含密钥、Cookie 或私人数据的原始导出。

## 审核时注意

- 对日期敏感的信息标注时间和复核要求；
- 将“用户明确说过”与“AI 从对话推断”分开；
- 删除凭据前保留必要的来源位置，不保留秘密本身；
- 相同主题优先补充现有知识，不创建平行页面。

导入后进入[审核知识](usage/review.html)，再通过[召回知识](usage/recall.html)验证结果。

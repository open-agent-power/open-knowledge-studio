# 备份与导出

备份用于保留知识库文件和修改历史，便于恢复或换电脑继续工作。导出用于把知识条目交给其他工具阅读，只包含导出范围内的内容。

```text
请检查当前知识库的未保存变更，并根据我的用途准备本地备份或知识导出；先确认保存位置，不覆盖已有文件。需要远端同步时，先向我确认仓库地址、权限和上传范围。
```

告诉 Agent 你想保留完整历史，还是把 Wiki 快照交给其他工具阅读：

| 用途 | Agent 应准备什么 |
|---|---|
| 备份或换电脑继续工作 | 用 Git 保存受版本控制的知识库文件与修改历史，并另外处理默认忽略的本机运行状态 |
| 交给支持标准 Markdown 的工具 | 导出 OKF 知识包，其中包含知识文件、标准链接和索引 |
| 在 Obsidian 等工具中阅读 | 导出使用双向链接写法的 Markdown，并说明适用范围 |

## 看什么结果

让 Agent 给出保存位置、备份或导出范围，以及失败或跳过的项目。导出会生成知识索引、链接和日志；打开几个条目，确认内容与链接符合预期。

Git 默认忽略 `.oks/`。因此，Git 备份通常不包含采集运行目录、缓存和其他本机状态。需要完整迁移时，应让 Agent 先检查忽略规则和实际目录，再决定哪些本机文件需要单独复制。

`oks wiki export` 会导出 `wiki/` 中所有能够解析的 Markdown 页面，不按 `status` 或归档状态过滤。导出结果可能包含 `provisional`、`stale`、`dropped`、`archived` 或 `superseded` 页面。交给其他工具前，应先检查导出清单和每页状态。

导出只包含知识快照，不能替代整个实例的历史备份。外部工具中的改动不会自动写回 OKS。查询索引可以从知识文件重建，但运行记录和未纳入版本控制的文件仍需单独检查。

本地备份不等于远端同步。上传资料前需确认目的地、访问权限和可上传内容，并取得明确的同步授权。

下一句可以说：“请打开导出索引，说明哪些内容已经导出、哪些没有包含。”格式参数见[CLI 参考](../reference/cli.html)。
